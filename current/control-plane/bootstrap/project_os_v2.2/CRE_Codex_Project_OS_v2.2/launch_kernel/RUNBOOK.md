# Launch Runbook

## Files to provide Codex

Required:

- actual `cre-foundry` repository or its current archive;
- `CRE_Codex_Launch_Kernel_v2.2.zip`;
- `CRE_Codex_Reference_Vault_v2.2.zip`;
- launch prompt.

## First run

Use interactive/Goal mode for `BOOTSTRAP-001`. It is the most ambiguous and
judgment-heavy stage.

Expected first artifacts:

- `artifacts/os_validation.json`;
- `artifacts/codex_capabilities.json`;
- `artifacts/context/current_task_packet.*`;
- repository inventory;
- contradiction report;
- evaluator topology;
- task DAG;
- next selected task.

## After bootstrap

Use headless runs for bounded tasks and tracker-backed orchestration for
continuous multi-task execution.

## Configuration

Do not blindly copy a stale config. Run the capability probe, inspect the
installed Codex config schema/help, then copy supported fields from
`.codex/config.template.toml`.

## Human inputs that remain real gates

- source authorization;
- firm service/economic priorities;
- protected accounts and relationship ownership;
- representative origins/capacity/specialty;
- credentials, spending, outreach, deployment, and promotion authority;
- external hidden holdout ownership;
- field and commercial outcomes.

## Safety

Use workspace-scoped permissions and legitimate approvals. Never launch with
dangerous bypass flags merely to reduce friction.

## Research and math sequence

After BOOTSTRAP-001, execute RESEARCH-001, EVAL-001, and MATH-001 before the integrated vertical slice. Access-dependent and empirical lanes remain gated rather than guessed.
