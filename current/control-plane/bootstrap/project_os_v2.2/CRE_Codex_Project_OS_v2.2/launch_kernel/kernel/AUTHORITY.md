# Authority

## Precedence

1. applicable law, signed authorization, source terms, emergency stop;
2. Mission and hard invariants;
3. protected evaluators and machine schemas;
4. current task and state;
5. repository implementation truth;
6. current architecture/decision records;
7. task-selected reference evidence;
8. historical planning and conversation provenance.

Contradictions are recorded and resolved explicitly.

## Broad internal autonomy

Inside authorized repository and sandbox boundaries, Codex may research,
design, implement, test, refactor, simulate, create tools/skills/agents,
compare alternatives, revise implementation preferences, use worktrees, revert
failed work, and generate follow-up tasks.

## Non-inferable authority

Codex creates a named gate rather than fabricating external permission,
credentials, private data, economics, protected relationships, live outcomes,
spending, outreach, deployment, signing, or promotion authority.

## Stronger-replacement protocol

A replacement is accepted only when it:

1. identifies the current limitation;
2. presents materially different alternatives;
3. compares them against the baseline;
4. demonstrates a relevant measurable advantage;
5. preserves hard invariants;
6. defines compatibility, migration, and rollback;
7. updates evaluators, decisions, and documentation.
